# 算力运维分享文档（方向：GPU 集群训练故障传导与监控闭环）

## 1. 选题背景与目标

本次分享选择的方向是：**“大模型训练场景下，GPU 集群故障如何沿链路传导，以及如何建设可落地的监控闭环”**。  
该方向同时覆盖硬件、网络、训练框架与平台运维，适合作为团队知识体系建设的主线专题。

目标是形成三层能力：

1. **看全局**：能从“机房-硬件-网络-调度-训练任务”看完整传导链。
2. **吃透一块**：每人深挖一个子域，形成原理和排障手册。
3. **做闭环**：监控覆盖、告警阈值、处置 SOP、复盘机制一体化。

## 3. 算力运维全局视角：故障传导路径总览

### 3.1 典型传导链路（从底层到训练结果）

```text
电力/散热异常
  -> 服务器降频或节点不稳定
    -> GPU 计算吞吐下降
      -> NCCL 同步变慢/超时
        -> 训练 step time 抖动
          -> 吞吐下降、训练时长拉长甚至任务失败
```

```text
交换机微突发拥塞
  -> RDMA 重传上升 / PFC pause 增多
    -> AllReduce 尾延迟放大
      -> 多机训练卡顿
        -> GPU 利用率下降 + 作业 SLA 违约
```

```text
数据存储抖动（对象存储/NAS）
  -> DataLoader 等待 I/O
    -> GPU 空转
      -> 训练吞吐下降
        -> 成本上升 + 迭代速度下降
```

### 3.2 故障传导分析表（可直接用于案例复盘）

| 故障源 | 传播路径 | 业务表象 | 关键证据指标 | 首要处置动作 |
|---|---|---|---|---|
| GPU ECC 错误 | GPU -> 进程异常退出 -> 作业重启 | 训练任务反复失败 | DCGM ECC error、Xid 日志 | 节点隔离 + 驱动/硬件检查 |
| RDMA 丢包 | 网络 -> NCCL 超时 -> 训练阻塞 | step time 周期性暴涨 | 重传率、NCCL timeout 日志 | 流量整形 + 拥塞点定位 |
| 调度碎片化 | 调度 -> 跨机通信劣化 -> 训练慢 | 同模型耗时差异大 | 作业拓扑分布、GPU 拓扑亲和性 | 调整调度策略/亲和性 |
| 存储抖动 | I/O -> DataLoader 阻塞 | GPU 利用率低 | IOPS/时延、DataLoader wait | 数据预热 + 本地缓存 |

## 4. “吃透一块 + 覆盖一块”的监控建设方法

### 4.1 监控分层与最小覆盖集

| 层级 | 必看指标 | 目标 |
|---|---|---|
| 机房/节点 | 温度、功耗、CPU steal、磁盘健康、GPU Xid | 发现硬件退化和节点风险 |
| GPU 层 | 利用率、显存占用、ECC、SM 时钟、NVLink 带宽 | 判断 GPU 是否高效且稳定 |
| 网络层 | RDMA 重传、端口丢包、PFC pause、交换机 buffer | 识别通信瓶颈和拥塞传播 |
| 平台层 | 调度等待时长、重试次数、节点驱逐、容器 OOM | 判断平台是否引入不稳定性 |
| 训练层 | step time、吞吐 tokens/s、loss 曲线、数据加载时延 | 度量训练真实效率与质量 |

### 4.2 告警分级建议

- **P1（立即处理）**：大面积任务失败、核心训练集群不可用。
- **P2（高优处理）**：训练性能显著下降，影响关键模型迭代。
- **P3（持续观察）**：单点异常或轻微抖动，未形成业务影响。

### 4.3 闭环动作标准

1. **发现**：监控告警 + 作业状态异常触发。
2. **定位**：按“节点 -> 网络 -> 平台 -> 框架”顺序排查。
3. **止损**：隔离故障节点、降级调度、切换训练策略。
4. **复盘**：补齐监控盲点，更新阈值和 SOP。

## 5. 近期进展汇报（逐人可讲模板）

> 目标：对应“每个人分头讲自己负责部分”的要求，以下模板可在周会/双周会上直接使用。

### 5.1 汇报模板（每人 5 分钟）

1. **我负责的子域**：一句话定义边界。
2. **近期完成**：本周期新增了哪些监控、案例、自动化动作。
3. **关键发现**：识别到的主要故障传导路径是什么。
4. **已落地改进**：阈值优化、SOP、自动化脚本、调度策略等。
5. **风险与下一步**：尚未覆盖的盲区和需要协同的问题。

### 5.2 示例（可替换真实姓名）

- **A（硬件方向）**
  - 完成 GPU Xid 与 ECC 告警规则重构，新增节点健康评分。
  - 发现“散热波动 -> GPU 降频 -> step time 抖动”的强相关链路。
  - 已上线故障节点自动摘除策略，降低重复故障影响范围。

- **B（网络方向）**
  - 完成 RDMA 关键端口指标接入，建立拥塞热点拓扑图。
  - 识别到“AllReduce 尾延迟”与交换机微突发拥塞高度相关。
  - 已将 PFC pause 异常纳入 P2 告警并补充处置 SOP。

- **C（训练框架方向）**
  - 对 DDP 训练任务增加 step time 分位数监控（P50/P95/P99）。
  - 发现数据加载抖动导致 GPU 空转，并被误判为算力不足。
  - 已推动数据预热与本地缓存策略，吞吐稳定性提升。
